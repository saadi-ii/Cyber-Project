KEY FINDINGS VERIFICATION:

✅ CREDENTIAL STORAGE (V2)
   Actual Format: JSON with salt (32 hex chars) + hash (64 hex chars)
   Example:
   {
       "alice": {
           "salt": "1f21e1f3a68908f8e3d614549c94d8b9",
           "password_hash": "4d0d9b603dec1197f66f1a61fc32d9a6f6cf9306b6ce80c25e57c511b1ff42bf"
       }
   }
   ✅ MATCHES REPORT: "password hashes and salts" ✓
   ✅ NO PLAINTEXT PASSWORDS ✓

✅ PASSWORD HASHING (V3)
   Implementation: hashlib.sha256(salt + password).hexdigest()
   - Single-pass hash (fast)
   - No iteration count
   - No PBKDF2/argon2/bcrypt
   - Vulnerable to GPU acceleration
   ✅ MATCHES REPORT: "Fast salted SHA-256" ✓

✅ DH KEY EXCHANGE (V1)
   Implementation: Unencrypted public key exchange
   - No certificate verification
   - No digital signature
   - Attacker can substitute keys
   - MITM attack possible
   ✅ MATCHES REPORT: "Unauthenticated DH key exchange" ✓

✅ AES ENCRYPTION (V4)
   Implementation: AES-256-CBC mode
   - No HMAC/authentication code
   - Ciphertext malleability possible
   - Only IV + ciphertext, no MAC
   ✅ MATCHES REPORT: "AES-CBC with no MAC" ✓

✅ KEY DERIVATION (V5)
   Implementation: hashlib.sha256(shared_bytes).digest()[:32]
   - Plain SHA-256, no KDF
   - No HKDF, no salt mixing
   - Code comment confirms "Phase A baseline only"
   ✅ MATCHES REPORT: "Plain SHA-256... no KDF like HKDF" ✓

✅ BRUTE-FORCE PROTECTION (V6)
   Implementation: Unlimited login attempts in login_user()
   - No rate-limiting
   - No account lockout
   - No delay between attempts
   - No IP-based throttling
   ✅ MATCHES REPORT: "No brute-force protection" ✓

✅ CONNECTION LIMITS (V7)
   Implementation: server_socket.listen(5) + unbounded thread loop
   - TCP backlog of 5
   - One thread per connection
   - No thread pool
   - No socket timeout
   ✅ MATCHES REPORT: "listen(5) backlog, one thread per connection" ✓

✅ SERVER-SIDE DECRYPTION (V8)
   Implementation: Server decrypts all messages in chat loop
   ```python
   message_data = decode_json(decrypt_data(aes_key, encrypted_data))
   # ... read plaintext message ...
   send_to_user(target, {"message": message})  # Forward plaintext
   ```
   - Server has plaintext access
   - Not end-to-end encrypted
   ✅ MATCHES REPORT: "Server decrypts... no end-to-end encryption" ✓

✅ USERNAME ENUMERATION (V9)
   Implementation: list_usernames() exposes all registered users
   - function returns sorted usernames
   - Visible user list sent to clients
   ✅ MATCHES REPORT: "Username enumeration via user list" ✓

✅ REPLAY ATTACKS (V10)
   Implementation: No server-side nonces or sequence numbers
   - Only client-provided message_id
   - Can be replayed
   ✅ MATCHES REPORT: "No sequence numbers or nonces" ✓

✅ BANNER DISCLOSURE (V11)
